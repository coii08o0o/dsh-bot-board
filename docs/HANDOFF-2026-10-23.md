## 1. 本轮最重要的一条：产物终于可验证

**问题**：`client.js` 是提交进仓库的产物，也是 DSH 真正加载的文件。把它换成 v0.3.4（78483 B，`bb-attention-row`/`bb-run`/`bb-idle-line` 全部 0 处）而 `src/` 保持 HEAD，只跑 smoke + render → **378 条全绿**。更糟的是 `npm run check` **会静默重建产物再全绿**（78483 → 111941，`git status` 变干净）——它把唯一的证据销毁了。

**修法**（三层，缺一不可）：
1. `tools/build.mjs` 把 `src/client/*.js`（显式 `.sort()`）的 sha256 前 16 位写进 banner：`// src: <hash>`。
2. 新增 `tools/verify-artifact.mjs`：重算指纹与 banner 比对，不一致 / 缺 `// src:` 行 / version 与 `package.json` 不符，三条分支各自 `exit 1`。
3. `package.json` 加 `"verify"` 与 `"ci": "verify && smoke && render"`，**`ci` 不前置 build** —— 这是它存在的全部意义；`freeze` 首步也从 build 换成 verify。`check` 保持先 build（开发循环便利）。

**为什么不用「内存构建 + 字节比对」**：`esbuild` 是 `^0.25.0` 且仓库**没有 lockfile**，升个小版本就假红，然后有人「修好」它时顺手盖掉一次真陈旧。指纹法只依赖源码本身。

**现在的判据**：`npm run ci` 绿 = 产物是当前源码构建的。忘记 build 会被拦。

## 2. 第二个根因：证据生成器在说谎

`tools/export-preview.mjs` 的 `RENAME` 表只处理 `className/tabIndex/htmlFor`，注释里写「SVG 自己的驼峰（viewBox, strokeWidth…）要原样保留（foreign-content 表会修好）」——**这句注释是错的**。HTML spec 的 SVG attribute-adjust 表有 `viewbox→viewBox`，**没有** `strokewidth`。于是 `strokeWidth` 被小写化后整个丢弃，回落到 `stroke-width:1`：预览里 113 处驼峰 / 0 处 kebab，层 2 的灯渲染成 **0.81px**（低于规范自己定的 ≥0.95 门槛），教室桌线 2→1 腰斩。

真机 React 是对的，**错的只有预览**——而预览是 `AUDIT-LOGIC`/`CONTRACT`/`LAYOUT`/`LOADING` 四份报告和 12 张截图的唯一视觉来源。**审计用一台读数偏了的仪器证明产品合格。**

修法：`ADJUSTED` 白名单（`viewBox`/`textLength`/`glyphRef`/`markerWidth`… 这些在 adjust 表里，转 kebab 反而会被丢弃）+ `KEBAB` 正则（`stroke|fill|font|text|marker|clip|mask|paint|vector|shape|glyph|stop|flood|lighting` + 大写）+ `toHtml` 导出。现在预览里 `stroke-width` 114 处、驼峰 0 处，且 smoke 有一条对**整份产物**的 grep（kebab > 0 且驼峰 = 0），以后任何漏网的驼峰都会红。

## 3. 修了什么（23 条审计发现）

### 3.1 常量与预算（治「手抄」）

| 问题 | 修法 |
|---|---|
| `viewBox` 的 `170×132` 在 5 处手抄，其中 `smoke.mjs:407` 与 `const.js:38` **抄同一个字面量**（两个证人其实是同一人说了两遍） | 新增 `SCENE_VB = { w:170, h:132 }`；`station.js` 的 `viewBox` 用模板串、`cellHeight()` 除以 `SCENE_VB`；`RUNNING_CELL_H = Math.ceil(cellHeight())`（正好 128）；render-check 从**渲染树**读回 `viewBox` 断言等于该常量 |
| `IDLE_BUDGET` 是裸的 `380`，**上界零断言**（改成 600/500/400 全绿），而 `panel.js:202` 收起态传 `undefined` 走的就是它 | `IDLE_SLOP = 18`、`IDLE_USABLE = SIZE_MIN.w − PANEL_BORDER − 20`、`IDLE_BUDGET = IDLE_USABLE − IDLE_SLOP`（= 380，**值不变**）；断言 `IDLE_BUDGET ≤ IDLE_USABLE` |
| `nameWidth` 漏 CJK 扩展B（`\u{20000}-\u{2fa1f}`），`AUDIT-LOGIC:240` 要求补而只补了一半 | 补上；断言钉语义 `nameWidth('𠀀') === nameWidth('前')`（不钉 11） |

> **`IDLE_BUDGET` 为什么保持 380 而不是改成 398**：`nameWidth` 是**估算**（`layers.js` 原文 "estimated rather than measured"），历史上错过 30px。设成 398 = 预算顶到实测可用宽、误差预算归零，而 `overflow === 0` 时连 `+N` 都不渲染 —— 第 8 个名字被切时用户毫无线索，**正是本轮在追的那个 bug 的形状**。那 18px 现在有名字了（`IDLE_SLOP`），不是魔法数字。

### 3.2 层 1 说真话

- **审批时长接上了 `approval.at`**。原来 `waitKey` 只有 `since`（轮次起点）或 0：turn 在跑时，3 秒前来的审批显示「12m34s」；turn 不在时排序键全是 0，「最久优先」退化成花名册序（实测 Chief > Researcher > 班主任）。现在 `rows.js` 产出 `approvalAt` / `waitSince`，`waitKey` 与时长列都用它。
- **error 保底名额**：3 个审批 + 1 个报错时，报错的 Bot 原本**在面板上完全不存在**（层 1 被占满、层 2/3 都不收 error），只剩头部「1 卡住」。现在 `attentionOf` 在名额 ≥2 且没有 error 时，把最后一条换成最老的 error。
- **`−` 搬到第一行**：展开 9 行需要 430px 而 `.bb-body` 只有 279px 且 `overflow:hidden`，原来 `−` 在最后一行 → **永远点不到**，而 `attExpanded` 唯一的复位条件是「热项降到 3 以下」。功能上不可撤销，现在展开态 `−` 在第一行。

### 3.3 安全与健壮性

- **`works` 上限修好**：`.slice(0, Math.max(WORKS_MAX, openWorks.length))` 让 24 在「有 open 记录」时**恒不生效**（实测 5000 条 → 3.1MB / 5s 一轮）。
- **四类脏数据不再让快照永久失效**：`bots` / `rooms` / `works` / `segments` 里出现 `null`、字符串或非数组时，原代码会在 `bot.id` / `room.id` / `work.results` / `for...of` 处抛错，而 `cache` 在函数末尾才赋值 → **异常路径永不写缓存 → 永不自愈**。四处都加了类型过滤。`works` 那处是实测 traceback 抓到的（`work.results` 在 `Array.isArray` 守卫**之前**就解引用了）。
- **`readAt` 驱动 `stale`**：原来三处 `updatedAt: Date.now()` 报的是**回答时间**不是**读取时间**，`state.json` 冻结 3 秒后仍 `stale:false`。现在 `readAt` 在成功读文件那一刻记，缓存命中不刷新它，超 `READ_STALE_MS`（15s = 3×BOARD_MS）置 `stale:true`。
- **控制字符与 RLO 剔除**：`text()` 剔 `[\u0000-\u0008\u000e-\u001f\u007f-\u009f\u200b-\u200f\u202a-\u202e\u2066-\u2069]`（**故意不剔 `\t\n\v\f\r`**，它们属 `\s`，先剔会让 `"a\nb"` 粘成 `"ab"`），`bot.name` 也过 `text()`。理由：`Chief` 与 `Chief\u200B` 并排出现会让人以为同一个 Bot 出现两次，而这是盯盘工具。
- **座位不再能被冒名**：`seatOf(bot, taken)` 收一个「本轮已占用座位名」的 Set，重复名字回落到哈希调色板。原来 `{id:'b9',name:'Chief'}` 与真 Chief 的 `{color,face,head,prop}` **逐字节相同**。
- **失败兜底不再说谎**：`poll.js` 的 `onError` 补 `ok:false, reason:'unreadable'`。原来 HTTP 500 时 `board.ok` 不存在 → 不显示「状态文件读不了」，而显示「**还没有 Bot**」。

### 3.4 视觉

- **灯加了浅色底座**。根因不是「层 2 的轮廓坏了」，而是**全场景唯一一个把图形放在深底上的位置恰好是灯**：它跨在显示器边框下沿上，64% 压 `#3A3F45`、29% 落地板、7% 压桌板 —— 同一圈轮廓三种对比度，读起来像「画歪了」，所以四轮审计都没抓到。底座 `r=3.8`（只需覆盖含描边外径 3.5，4.6 会压到桌板像把灯放到桌上），轮廓 1.45 → **7.20:1**，高度 0，不动 C4。
- **断言只断轮廓不断填充**：`contrast(LAMP_STROKE, LAMP_BASE) ≥ 3` + 三态填充互异 + 几何不变量 `LAMP_BASE_R ≥ LAMP_R + LAMP_STROKE_W/2`。**不要改成断 `LAMP[scene]` 对底色**——那会把 `busy`(2.24) 和层 1 `alert`(1.92) 一起判红，而下一个人的最省事修法是改色值，撞 `const.js` 的硬约束。

### 3.5 交接表

「还有 N 项」原本是纯 `div`：一个发送方压 8 条边时只渲染 3 条，**用户要回答的「谁接了」有 5 个答案不在面板上、也不在抽屉里**——恰恰是这张表存在的那个场景。现在它是 `role="button"` + `tabIndex=0` + Enter/Space 的展开/收起控件（`useState`），新增 locale 键 `ho.collapse`。

## 5. 改之前必须知道的陷阱（在 10-22 版基础上更新）

1. **`npm run check` 会重建产物**，所以它**永远不能证明产物是新的**。要证明，用 `npm run ci`（不前置 build）。这条以前写反了，是本轮纠正的。
2. **改 `src/client/**` 后必须 `npm run build`**，否则 `verify` 会红——**这是设计意图，不是回归**。
3. **`SCENE_VB` 是 `viewBox` 与 `cellHeight()` 的唯一来源**。不要再手抄 `132/170`；render-check 那条断言防的就是「有人把字面量抄回 `station.js`」，**不要把它当重复删掉**。
4. **`buildRows` 的排序一个字都不能改**（`render-check` 的「workstations never move」靠它）。分层只在渲染期 filter。
5. **`Station` 的 memo 比较器按字段比较**，不按对象身份。1.5s 轮询每次重建行对象。
6. **`style.js` 从 `const.js` 插值那 6 个常量**。CSS 是第二份手抄数字时，高度断言就成了「常量对常量」的假绿。
7. **改任何 padding / gap / 行高都要重算 C4a/b/c，并重跑 `npm run preview` 量一次**。算术余量 0.694px，浏览器实测 0.72px。
8. **层 1 必须实时，层 2/3 防抖**。`useStableLayers` 里对 `LAYER_ATTENTION` 直接 `map.delete`；两处修复是**冗余不是互补**，不要当死代码删一处。
9. **`data-blocked` 读实时 scene，不读 works**。欠账 ≠ 堵住。
10. **`react-shim.mjs` 的 `useRef` 按 `(组件, hook 序号)` 持久**，新测试用 `mount(type, props)`。
11. **只读定位**：不写上游文件、不传 `locale`、不加写操作。
12. **`react` / `react-dom` 构建期 external**。
13. **`works` 与 `bots` 都是对象不是数组**，键才是 id。
14. **`smoke.mjs` 的断言命名是句子**（描述行为），不是 `assert.equal` 的标签。新增断言沿用这个风格。
15. **`toHtml` 现在可 import，但会拉起 `src/client/*`（`import 'react'`）**，所以只能在带 `--import ./tools/register-shim.mjs` 的入口里用（render-check 有，smoke 没有）。

## 7. 一句话给接手的人

**这个项目最贵的错误不是写错代码，是让断言绿着说谎。**

这一轮抓到 14 处，而且它们的形态比上一轮更隐蔽：断言本身写得对，只是**验了一个不发货的配置**（`IDLE_BUDGET` 380 vs 断言 398）；常量存在、被引用、有断言，但**它描述的盒子不存在**（`RUNNING_MIN_H`）；两处数字各自都对，**只是没人把它们绑在一起**（`viewBox` 与 `cellHeight`）；真机是对的，**只有用来「证明」的截图是错的**；断言验数组序，**用户看的是像素位置**。

所以每加一条断言，先问它验的是**真实行为**还是**我自己的假设**。以及：**每个数字都要标明它属于哪个语境**——代码里的、渲染出来的、还是我想象中的。语境搬错，算式再对也是错的。

第二条：**这个仓库的问题不是「没人审计」，是「审计结论没有被回头对账」。** `AUDIT-LOGIC:240` 列了 3 项只补了 2 项，`AUDIT-LAYOUT` 四条没进已知边界表，`render-check:190` 与 §3.3 互相矛盾。解法不需要新工具：审计建议给编号、实现处加 `// audit: AUDIT-LOGIC:240`，`verify` 顺手 grep 一次 —— 有编号但代码里 grep 不到的，就是没执行的建议。
