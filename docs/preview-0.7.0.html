dsh-bot-board v0.7.0 · 三层注意力轴

下面每一块都是真实组件渲染出来的：同一个 Head / Body / LegendSheet / Drawer，同一份 CSS 字符串，同一套 buildRows。不是 mockup，所以它不会展示一个不存在的界面。

这份导出的用途只有一个：把「装得下」这件事从算术变成看得见。检查环境没有布局引擎，C4a/b/c 全是预算断言；浏览器有布局引擎，所以这里能验、也能证伪。它验不了「第一眼落在哪」——那个要人看。

1默认尺寸 · 3 件需要你 + 5 个在动（C4c 临界）

9 个 Bot 满员：3 需要你 + 5 在动 + 1 闲着。C4c 的全部项：2(面板边框) + 39 + 3×44 + 2×3 + 10 + 2×127.15 + 8 + 4 + 24 = 479.31 ≤ 480。v0.4.0 在这里超 12.8px 出滚动条；v0.4.1 第一版按 139 收窄仍然超 0.9px，是这份导出量出来的。现在 267/267，第二行名字完整、零滚动。

2默认尺寸 · 同样 5 个在动，但带交接边表

⚠ 的 70px 全部来自交接边表。`.bb-run` 是面板唯一的滚动区，边表向下延伸需要滚才看全——这是有意的：它解释的是上面那些人，不必常驻。工位网格本身完整。

3最小尺寸 · 2 件需要你（设计基准，不是降级态）

F2：两行都完整可见（工位网格 131px ≤ 在动 154px）。头部原来在这里裁掉 33px（实测需要 288 / 可用 255，「最久 4m12s」被切一半），v0.4.1 把那一项移除了，现在 222/222。⚠ 的 30px 来自交接边表，不是网格。

4退化态 · 9 个全 alert（层 1 封顶 + 溢出 chip）

3 行 + `+6` chip。以前第 4 个人在整个面板里没有名字、点不开；现在 chip 是 role=button，点开就是全部 9 行。

5溢出态 · 收起 / 展开（同一个快照）

左：3 行 + `+2`。右：点过 chip 之后，5 行全在，chip 变成 `−` 可以收回。高度代价在收起态是 0。两张图下方都是名册——没人在跑、也没有未结交接，所以四个闲着的 Bot 各占一行；展开态 242 + 4×44 = 418 ≤ 478，仍然不滚。

6退化态 · 全 idle（名册形态）

一行摘要 + 九行名册。560×480 是单列（9×44 + 摘要 38 = 475 ≤ 480）；420×320 自动分两列，一行不藏在滚动里——列数由剩余高度算出，不是断点。名册不是层 1 的灰色版：没有白卡、没有灯、名字 500 字重，只有 `!` 徽章还是那个徽章。

7语义红线 · 接收方 busy 的边 + A↔B 互相等

Bot1→Bot2 的接收方在干活 → 不带「被堵」（去催一个正在还账的人是错的）。两条边都标 `⇄ 互相等`，两侧各保留自己的计数。

8抽屉 · 审批原文

头部那个灯和现场是同一个 Lamp 组件（14px）。以前是 8px 纯色点，没有形状，读者没法把它和学过的形状对上。

9身份来源 · 上游 shape/color > 哈希

三个 Bot，三种来源。Chief 带了上游两轴（`avatar.shape: whale` + `color: deepseek`）：轮廓和身体色都来自 DS Bot。Bob 只带了 shape（star）：轮廓听上游，颜色按 id 哈希补。第三个什么都没带：两轴都哈希，得到一张稳定的脸。桌面道具一直是哈希的——上游没有描述它的字段。名字不参与任何一级。
