## 2. 关键决策（含被推翻的需求）

### 2.1 用「三层」而不是「按状态分区」——推翻了使用者的原始选择

使用者原本选了「按状态分区」。**没有照做**：

分区解决的是「找得到」，但他的原话是「淹没在一片工位里、要挨个扫」——那是**看得见**的问题，是尺寸和对比度。搬完那盏灯还是 27px²，还得挨个辨形状。**搬完还得放大，不如直接放大。**

而且分区的代价是他自己在 0.3.x 攒下的资产（「位置是你记人的方式」），而「等你」的出现与消失恰好最频繁。

现在的方案：**位移只在「真的有 Bot 开始/结束一轮」时发生**——最低频、且本身承载信息。颜色变了这种高频事件零位移。

### 2.2 `works.open` 是「转包出去没交回的子 work 数」，不是「欠 N 项」

上游 `ds-bot/src/host/handoffs.js:32` 写的是 `works()[id] = { from, to, open: [], results: [], at }`，然后 `if (above) above.open.push(id)`。所以 `open` 是**子 work id 数组**，`waits = open.length > 0` 才是「在等」。

宿主 `src/host/index.js` 用 `open: Array.isArray(work.open) ? work.open.length : 0` 转换，**这个转换是对的**，`open.length` 就是「在等几个人交活」，UI 显示「N 项待交」语义正确。

**审计期间有一条 P0 声称这里反了，是误报。** 但审计发现的另一半是真的：`state.json` 里 `open: []` + `results: []` 的记录可能是**僵尸**（创建后从未 `closeWork`），显示 0 项在交接是正确行为，不是漏显示。

### 2.3 `works.open > 0` 不等于「此刻被堵」

**语义红线。** `open > 0` 只说明「还有子 work 没交回」，不说明「现在被堵住」——一个 Bot 可能一边欠着一边正在飞快还账。所以 `data-blocked` 由**接收方当前 scene** 决定（`handoffs.js`）：

- `alert` / `error` → `"true"`，加「被堵」
- `busy` / `waiting` → `"false"`，无强调
- `idle` / 未知 → `"idle"`，加「未开工」

真正的「此刻谁在等谁」在 `work.waiting[botId].bots` 活数据里。把欠账画成堵住，用户会去催一个正在干活的人。

### 2.4 交接表放在工位网格**之前**

硬算：层 2 可用 269px，6 个工位 2 行 = 268px。**交接表和 6 个工位不可能同时完整可见。**

而那一刻正是它最重要的时候——刚对班主任说完「八科都过一遍」，8 个在跑 + 8 条边同时存在。既然滚动不可避免，先看关系：工位位置固定、有肌肉记忆；交接关系是新信息。头部 `N 项在交接` 负责完全不滚动时的回答。

断言钉着：`the hand-off table comes before the workstation grid (0 < 1)`。

### 2.5 图例从常驻降级成抽屉

原来顶部那行 27px、六色、**每 tick 渲染、永不变化、位于视线第一落点**。现在是一个 24px 的 `?` 按钮。

### 2.6 层 1 不参与防抖（P0 根因）

`useStableLayers` 原本对所有层归属加 1200ms 防抖，但 `Body` 里层 1 又按**实时** scene 过滤一次。两道过滤不同步：审批到来时头部说「1 等你」而层 1 说「没有需要你的事」；审批处理后那个 Bot 三层都不在，9 个 Bot 数得出 8 个。

修法：层 1 用实时 `layerOf(row)`、`useStableLayers` 里对 `LAYER_ATTENTION` 直接 `map.delete`；层 2/3 用 `stable ?? live` 回落。

**两处修复是冗余不是互补**（单独回滚任一处都全绿），这是 P0 上故意的纵深防御，不要当死代码删一处。

## 5. 改之前必须知道的陷阱

1. **不需要「退出 DSH 重开」**——客户端半边有 HMR，`npm run build` 后重建即生效（143 条 code cache 条目实证）。**但 HMR 只覆盖客户端**：改 `src/host/**` 必须重启 DSH 才生效。这条以前写反了，是审计纠正的。
2. **`buildRows` 的排序一个字都不能改**。`render-check` 的「workstations never move」靠它。分层只在渲染期 filter。
3. **`Station` 的 memo 比较器按字段比较，不按对象身份**。1.5s 轮询每次重建行对象。现在比较器含 `compact` 和 `onOpen`。
4. **`style.js` 从 `const.js` 插值那 6 个常量**。不要再手抄数字——CSS 是第二份手抄数字时，高度断言就成了「常量对常量」的假绿。
5. **改任何 padding / gap / 行高都要重算 C4a/b/c，并重跑 `npm run preview` 量一次**。算术余量 0.72px。
6. **层 1 必须实时，层 2/3 防抖**。见 §2.6。
7. **`data-blocked` 读实时 scene，不读 works**。见 §2.3。
8. **`react-shim.mjs` 的 `useRef` 按 `(组件, hook 序号)` 持久**，`mount(type, props)` 把组件当元素挂载。直接调用组件会让 refs 写进上一个组件的 store。新测试用 `mount`。
9. **只读定位**：不写上游文件、不传 `locale`（上游是全局 `uiLocale`）、不加写操作。
10. **`react` / `react-dom` 构建期 external**，打进 bundle 会产生第二份 React，hooks 直接报错。
11. **改完必须 `npm run build`**，`client.js` 是产物。
12. **`works` 是对象不是数组**，键才是 work id，值里没有 `id` 字段。宿主已用 `Object.entries` 处理。
13. **`bots` 也是对象不是数组**（README 里写 `bots[]` 是误导）。

## 8. 一句话给接手的人

**这块面板的全部价值在「没事的时候敢不看」。** 任何改动都要先回答两个问题：它有没有让「有事」更早被看见？有没有让「没事」更安静？答不上来的改动，不管多好看，都是在稀释这个价值。

第二条：**这个项目里最贵的错误不是写错代码，是让断言绿着说谎。** 这一轮抓到三处——`'daibe'` 把排序方向固化成反向、C4c 漏算 12px 声称「默认尺寸不用滚」、设计规范拿层 1 的性质描述层 2。它们的共同点是：**测试和文档都在验证一个不存在的界面**。改任何东西之前，先问「这条断言/这句话，验的是真实行为还是我自己的假设」。
