02场景一 · 有 Bot 在动（560×480）

层1 空态 38px，层2 三个工位（班主任 / 数学 / 化学，busy 绿），层3 一行 24px。这是最常出现的样子。

读数顺序是刻意的：先数量（还能派几个）→ 再最久（谁最该被派活）→ 再次久（备胎）。

两个时长槽是常驻的：只有一个够格时，第二个槽留空占位，行宽不跳。

≥1h 只加 700 字重，不上色：琥珀 #B45309 已经是层1 alert 左条的色位，层3 几乎每屏都有一个 ≥1h，占用它就等于把那个色位取消掉。红黄绿同样是灯的语言。

03场景二 · 全部 idle（560×480）

层2 不渲染。层3 从 24px 涨成「24px 计数行 + 377px 名册区」，正好吃下原来层2 的那 377px；名册 3 列 × 3 行、格高 32px、总高 108px，靠上对齐，下面 269px 留白。

名册按 ROSTER 座位顺序排：Chief / Researcher / 班主任 · 数学 / 物理 / 化学 · 生物 / 语文 / 英语。座位顺序固定，所以「物理在化学左边」这件事每次都成立，扫视靠位置记忆。

计数行与常态行是同一个组件（只去掉「全部 ›」，第二个时长槽留 62px 空位补齐），所以行内不重排、不跳宽。但整行会从面板底部（y≈415）移到顶部（y≈38）——位移 377px（560）/ 217px（420），这是层2 消失的代价，不是免费的重排。

化学 1h 是 ≥1h 的边界样本：它加粗，8m / 12m / 25m 不加粗。

04最小尺寸 · 420×320 两张

同一个面板缩到 SIZE_MIN。层3 两态都还成立：常态 24px、名册 241px（24 + 217）。名册在 418 宽里仍是 3 列 × 3 行 = 108px，在 217px 里余 109px。

05这个原型验证了什么 / 没验证什么

面板与层高都是从真实 DOM 量出来的（见每个面板下面的实测值），不是按预算表推的。

验证了（可以在真机上直接对照）没验证（这一版原型管不到）
  1. 24px 行在 558 / 418 两个内宽里都不换行、不裁切：新行内容 270px，560 余 288px、420 余 148px；右侧「全部 ›」右对齐，行高恒 24px——旧行同高，480/320 的高度预算没有变化。
  2. 计数是两段字：6 11px/700 + /9 11px/400，零间距，读起来是一个分数而不是两个词。
  3. ≥1h 只加粗，不上色：琥珀 #B45309 留给层1 alert 左条，红黄绿六个灯色一个没动；1h 作为边界值也走加粗分支。
  4. 全 idle 时层2 让位、层3 铺开：560 下 401px（24 计数 + 377 名册区），420 下 241px（24 + 217），都靠上对齐，无第二个滚动区。
  5. 两个常驻槽：全 idle 计数行的第二个槽留 62px 空位（.is-empty），行内结构不重排；但整行会从底部移到顶部，位移 377px / 217px。
  6. 名册 3 列在两档都成立：108px（3×3），560 余 269px、420 余 109px；格内 112.67px 装得下「Researcher 40m」（92px）。
  1. 真实数据：时长是推导字段（最后一条消息 / 回合的时间戳），原型里是手写常量。跨天（1d 3h）、超过 24h、从未说过话（—）三种边界还没设计。
  2. 真实字体度量：这里用系统字体，宿主 DSH 主题的 font-family 不同，Latin 名字宽度会差几 px；两个时长槽在「只有一个够格」时用 .is-empty 占 62px，这个占位宽度需要在真机上再校一次。
  3. 动效：24px 行 ↔ 401px 名册之间怎么过渡（有没有动画、多长、层2 是淡出还是直接消失）完全没做，这是静态快照。
  4. 交互：「全部 ›」的展开态、名册每格点开抽屉、hover 在深色主题下的观感都没做。键盘可达性只做到「能 Tab 到 + 有焦点环」（role="button" tabindex="0"），Enter/Space 的实际行为没有。
  5. 身份：名册只有文字，9 个 seat 色在全 idle 时完全消失。要保住身份就得加 6px 色点，会占掉约 12px 宽——这个需要再拍一次。
